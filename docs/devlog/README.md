# 开发编年史（devlog）

按「阶段」记录 agent-crowd 从 0 到 1 以及之后的演进。**为什么、踩了什么坑，比结果本身更值钱**；这些是写给「未来想复刻这套思路的团队」和「几个月后忘了细节的自己」看的。

三层文档各管一件事：

| 层 | 路径 | 管什么 |
| --- | --- | --- |
| 现在长什么样 | `docs/architecture.md` | 模块图、turn 生命周期、DB、契约；随演进**更新** |
| 什么时候怎么演进的 | `docs/devlog/NNNN-*.md`（本目录） | 每个阶段一篇，编号单调递增，**永不重排、永不删除** |
| 当初为什么这么选 | `docs/adr/NNNN-*.md` | 只记「当时有 A/B、最后选了 B 为什么」 |

## 什么时候必须补一篇（触发规则）

review checklist 有一条固定问题：**「这轮该不该有 devlog？」** 出现以下任一情况，答案都是「要」：

- 新增 / 重写 harness 适配器
- DB schema 变更（加表、加列、改语义）
- 更换默认 provider / 模型供给方式
- P0 运维事故（生产 server 异常、重启失败、数据问题）
- 用户可见的行为语义变化（触发规则、失败语义等）

## 怎么写

1. 生成草稿骨架：`node scripts/devlog-draft.mjs`（自动从上次记录的 commit 起拉取提交清单）；
2. 填空：背景/目标 → 做法 → 关键决策（链 ADR）→ 踩坑 → 验证 → 遗留 → **如果重做一遍只改哪三处**（这节最值钱）；
3. 定稿：把文件名里的 `draft-` 去掉，编号保持不动；
4. 重建本页索引：`node scripts/devlog-draft.mjs --index`；
5. 提交前 `npm run docs:check` 校验必填小节齐全。

素材来源：git log 的中文提交信息、群聊 DB 里的真实争论、设计稿（`docs/memory-plan.md` 等，只链接不复制）。**按阶段记，不逐 commit 记。**
