# ADR-0010：默认响应者用房间设置，角色用固定标签而不是动态调度

- 状态：已接受
- 日期：2026-11-24
- 关联：devlog 0003

## 背景

房间没有 @ 时固定由“第一个启用的角色”接手。角色一多，这个隐式规则就会把总结、问答、实现都塞给同一个角色；Clowder 用 roster（roles/family/lead）做能力分工，但它假设有较多角色和动态配对。Agent Crowd 通常只有 2–4 个角色，需要一个更轻、可预测的版本。

## 候选方案

- **方案 1. 复制 Clowder roster**：按能力/负载自动派活。灵活，但角色少时收益低，且难以解释“为什么这次是它答”。
- **方案 2. 只加 @ 点名**：不改路由，用户每次手动 @。简单，但问答/总结仍要记名字。
- **方案 3. 房间默认响应者 + 固定角色标签**：默认响应者解决“没人 @ 谁答”；roles 只用于 reviewer 池和展示，不自动派活。

## 决定

选方案 3。它对应需求里的 **A（默认响应者）+ B（角色标签 / reviewer 池）**，不是另一个未立项的 C 项。

- `rooms.default_responder_id`：没人被 @ 时优先它；停用/删除时回退到第一个启用角色。
- `characters.roles`：固定词表（architect / implementer / reviewer / summarizer / assistant），只做标签与 reviewer 选择，不做意图识别。
- `server/reviewers.ts` 统一选择：指定 reviewer 优先；否则从 `reviewer` 标签里选；否则回退任意合格角色（兼容旧房间）。作者本人、同 harness、轮末总结角色一律排除。
- 池里选中的 reviewer 会绑定到本轮 `RoundState`；门禁收尾时重新读取它的当前记录（停用/删除 → fail closed，改 harness → 用新 harness 判断独立性），再校验 PASS 作者和 harness，避免“任意非实现者、哪怕同 harness”放行。盲审配置失效时仍允许一次 PATCH 关闭盲审，不会死锁在无法保存的房间设置里。
- 角色库模板暂不携带 roles，避免动 preset 数据链；房间内手动勾选一次。

## 后果

- **收益**：问答/总结可以明确落到指定角色；reviewer 从“必须指定一个”变成“指定或角色池”；路由规则仍然可预测，不需要意图分类器。
- **代价**：默认响应者和角色标签都是房间局部配置，换房间要重设；角色库不携带标签，新角色需要手动勾一次。没有自动负载/能力调度。
- **不做**：不做 LLM 意图路由、不做跨房间共享角色配置、不把 Clowder 的 roster/lead 机制搬过来。
