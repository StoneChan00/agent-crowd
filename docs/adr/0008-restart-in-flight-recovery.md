# ADR-0008：重启自愈只自动续跑「有部分产出」的在飞回合

- 状态：已接受
- 日期：2026-11-23
- 关联：devlog 0003、ADR-0005

## 背景

排队中的回合已经持久化，重启后能恢复；但正在跑的回合被硬杀后只会被标成 `error`，用户必须手动重发。实际使用里，长回合常常已经产出了半截有用内容（分析、代码、诊断），丢掉重来既慢又贵。反过来，零产出的回合可能是刚启动、也可能已经产生了副作用但还没输出文本，自动重跑有风险。

## 候选方案

- **A. 不做**：保持现状，重启只恢复队列；在飞回合由用户重发。
- **B. 全部自动续跑**：running 一律续跑一次。实现简单，但零产出任务可能重复执行有副作用的操作。
- **C. 只续跑有部分文本的回合**：运行中每 2 秒 checkpoint 已流出的文本；重启后只对 `output.trim()` 非空的回合自动续跑一次。

## 决定

选 C。

- 运行期 checkpoint：`emit` 里每 2 秒把 `replay.text` 写回 `turns.output`（硬杀没有退出钩子，这是唯一的落盘机会）。
- 启动后：`startupRecovery` 仍把所有 running 标成 `error`；`recoverInterrupted` 只处理有部分产出的回合：
  - 先把部分输出作为一条带 `meta.error = 服务器重启中断的部分输出` 的角色消息放回群聊，让续跑的 prompt 能看到它；
  - 再以新 round 入队一次「从中断处继续」的恢复回合，`restart_recovery=1`。
- 跳过：轮末总结回合、零产出回合、同房间还有排队回合（避免 RoundState 错位）。
- 恢复回合自己再次被中断时不再自动恢复，防止重启循环。
- `AC_RESTART_RECOVERY=0` 可关闭整个自动续跑，保留原有队列恢复。

## 后果

- **收益**：重启不再无条件丢弃在飞的长任务；续跑有明确的「已完成/继续」边界，用户能在群里看到部分输出和恢复通知。
- **代价**：续跑是全新 CLI 会话（完整重放上下文 + 部分输出），不是恢复被杀的会话，token 成本高于 M3 的会话续跑；2 秒 checkpoint 会带来少量额外 SQLite 写入；零产出任务仍需用户手动重发。
- **不做**：不做逐 token checkpoint、不持久化工具调用栈、不自动恢复总结回合。
