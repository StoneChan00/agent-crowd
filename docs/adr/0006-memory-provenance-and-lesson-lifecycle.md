# ADR-0006：记忆必须有来源，失败教训要有生命周期

- 状态：已接受
- 日期：2026-11-19
- 关联：devlog 0003

## 背景

自动 episode 和失败教训都是模型之外生成的记忆。没有来源时，用户看到一条「本轮完成：改动 a.ts…」无法核对它对应哪条消息、哪一轮；出了问题只能翻聊天记录猜。失败教训则相反：每条都钉选会挤占 prompt 预算，全部不钉选又会在下一次失败时丢失上下文。

## 候选方案

- **A. 记忆只存内容 + sourceRoomId（现状）**：实现最轻，但不可追溯。
- **B. 全量 evidence graph**：每条记忆引用消息、轮次、工具调用、diff；查询能力强，但 schema 和 UI 都重。
- **C. 最小溯源 + 经验证的优先级**：只存 `source_message_id` / `source_round_id`，UI 能跳回原消息；教训按出现次数升级、按时间降权。

## 决定

选 C。

- 所有记忆可带 `source_message_id` / `source_round_id`；手动「记住」写消息 id，自动 episode/lesson 写 round id。
- 同 hash 教训再次出现时 `repeat_count + 1`、刷新 `last_seen_at`；第二次出现升级为 `promoted`，不再被「只保留最新一条钉选」的规则挤掉。
- 常驻教训 90 天未再出现自动降权（解除钉选、保留记录）；不删除，避免不可逆的数据丢失。
- 最新一条未升级教训仍然钉选，保证下一次尝试能看到最近的根因。

## 后果

- **收益**：每条自动记忆都能回到现场；重复问题变成稳定约定，偶发问题不会永久占据 prompt；阈值集中在 `server/db.ts`，可调。
- **代价**：`promoted` 教训可能累积多条（按不同根因），挤占 room 记忆预算；90 天阈值对长期项目可能偏短或偏长。记录仍可手动取消钉选或删除。
- **不做什么**：不做 evidence graph、自动合并同类教训、跨仓库知识对象。等真实使用证明需要再说。
