## 代码审查清单（通用）

按以下顺序过一遍改动，逐项核对后再给结论。这份清单只覆盖通用工程规范，具体项目约定以仓库内文档为准。

### 正确性
- 变更是否解决了它声称要解决的问题；边界条件（空输入、单元素、超长、并发重入）是否想过。
- 错误路径是否处理：失败时资源是否释放、状态是否留在可用态、用户能否看到失败原因。
- 与改动同域的既有测试是否仍然成立；新行为是否有能失败的断言锁住（不是恒真断言）。

### 影响面
- diff 是否只包含本任务必要的改动；有没有顺手重构、格式漂移、无关文件被卷入。
- 公共接口/数据格式的变更是否向后兼容；老数据、老调用方是否仍然可用。
- 配置、迁移、脚本是否与代码同步更新。

### 可维护性
- 命名与既有代码风格一致；复杂分支有注释说明「为什么」而不是「是什么」。
- 新常量/魔法数字是否有出处和单位；删除的代码是否真的不再被引用。

### 验证与交付
- 自述的验证步骤别人能否原样复跑；声称「通过」的命令是否真的执行过。
- 汇报里如实区分：已验证的事实 / 未验证的推断 / 已知风险。
- review 结论按房间门禁格式单独成行，问题描述可操作、可复现。
